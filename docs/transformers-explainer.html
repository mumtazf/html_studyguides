Discussion primer

How Transformers Work

A high-level, click-through tour of the architecture behind modern LLMs. Enough to hold a room — the deeper math can come later.

00

The one-sentence version

A transformer takes a sequence of words and, at every position, lets each word look at every other word to build a context-aware understanding. Stack that operation many times and you get a model that can predict what comes next.

The pipeline

1. Tokenize — chop text into tokens (word-ish pieces)
↓
2. Embed — turn each token into a vector of numbers
↓
3. Add position — mark where each token sits in the sequence
↓
4. Self-attention — every token gathers info from the others
↓
5. Feed-forward + repeat — refine, then stack the whole block N times
↓
6. Predict — output a probability for the next token
The famous idea from “Attention Is All You Need” (2017): drop recurrence entirely and let attention do the heavy lifting. That's what makes transformers so parallelizable — and so good.

Kick off the discussion

  • Before this, models read text one word at a time (RNNs). What might be hard about that?
  • What does it buy us to let every word see every other word at once?
01

Tokens & embeddings

Models don't see letters — they see tokens, then convert each token into a vector (a list of numbers) called an embedding. Similar meanings end up with similar vectors.

Real embeddings have hundreds or thousands of dimensions and are learned from data. The bars here are illustrative — the point is: every token becomes a point in a high-dimensional space.

Talking point

  • Why is “a list of numbers” a better representation for a computer than the raw word?
02

Where's the word? Positional information

Attention looks at all tokens at once — so on its own it has no sense of order. To the model, a sentence is a bag of word vectors. So before attention, we add a positional signal to each token's embedding: same word, different slot → different vector.

Why we need it — “dog bites man”

Swap the words. Without position, the model sees the same set of vectors either way. Add position and each slot becomes distinct.

What the signal looks like — position × dimension

Every row is one position's fingerprint; every column is one dimension. Left columns are slow waves, right columns are fast. Slide to highlight a position.

−1+1

The original paper uses sine/cosine waves of different frequencies. Two things fall out of this: every position gets a unique pattern, and nearby positions look similar — so the model can also sense how far apart two tokens are. Modern models use variants (learned or rotary), but the goal is identical.
03

Self-attention: the heart of it

Every token asks a Query (“what am I looking for?”), and every token offers a Key (“here's what I am”). Match a query against all keys to get attention weights — how much each token should pull from every other. Those weights then blend the Values.

Attention map — click a row (a query token)

Each row shows where that token “looks.” Brighter = more attention. Weights in a row add to 1.

lessmore attention
Causal mask forces each token to only look at itself and earlier tokens — never the future. That's what lets a model generate text left-to-right. (You built a whole guide on this — see the Attention Mask Explorer.)

Talking points

  • Turn the mask on — how does the shape of the map change, and why?
  • For the word “it” in a sentence, which earlier words should it attend to?
  • Q, K, and V are three different learned “views” of the same token. Why not just use the raw embedding for all three?
04

Many heads, many perspectives

One attention map captures one kind of relationship. Multi-head attention runs several in parallel — each head can specialize (one tracks grammar, another tracks who-did-what, etc.) — then combines them.

Switch between heads

Same sentence, different head — notice each one lights up a different pattern.

In practice a model might have 12, 32, or 96 heads per layer. More heads = more relationship types the model can track simultaneously.
05

Stack the blocks, then predict

After attention, each token passes through a small feed-forward network that refines it. Two more tricks keep training stable:

One transformer block

Multi-head self-attention — mix information across tokens
↓ + residual connection (add the input back) & layer-norm
Feed-forward network — refine each token on its own
↓ + residual & layer-norm again
Output → feeds into the next identical block

Residual connections give gradients a shortcut so very deep stacks still train. Layer-norm keeps the numbers well-behaved.

Stacking

The final block's output at the last position goes through one more layer that produces a probability for every possible next token. Pick one, append it, and repeat — that's text generation.

Wrap-up questions

  • Early layers tend to learn simple patterns; later layers learn abstract meaning. Why might depth create that hierarchy?
  • If generation is just “predict the next token” over and over, where does the appearance of reasoning come from?
