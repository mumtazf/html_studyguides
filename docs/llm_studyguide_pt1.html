Language Modeling Fundamentals

~6:00 – 9:00

Language models are probability distributions over token sequences. Slides 10–13

What Language Models Do

  • Model text: Assign probabilities — higher for plausible text, lower for nonsense
  • Generate text: Sample from the learned distribution
  • Distinguish valid from invalid: Higher likelihood = more coherent
P("The cat sat on the mat") >> P("Mat the on sat cat the")
Core Insight: A language model assigns a probability to every possible string. Good text gets high probability; bad text gets low probability. This single mechanism enables both understanding and generation.
🔑 Key Takeaway: Language models learn a probability distribution over sequences — this single mechanism enables both understanding and generation of human-like text.

Autoregressive Models & Sampling

~9:00 – 12:00

Autoregressive (AR) models factor sequence probabilities via the chain rule: Slides 14–16

P(x₁, x₂, …, x_L) = ∏ P(xᵢ | x₁, …, xᵢ₋₁)

The probability of a full sequence = product of each token's conditional probability given all preceding tokens.

Sampling Loop

1. Context
→
2. Compute P(next)
→
3. Sample token
→
4. Append & repeat

Trade-offs

AspectDetail
✅ UpsideExact factorization; well-understood; widely used
⚠️ DownsideSequential generation → latency grows with output length

Example (from slides) Slide 15

Input: "She likely prefers" → model computes P(next | context) for all vocab tokens, then samples — might predict "dogs", "coffee", etc.

Step-by-Step

  1. Tokenize raw text into subword tokens
  2. Embed tokens into dense vectors
  3. Pass through Transformer layers → contextualized representations
  4. Linear projection to vocab-sized logits
  5. Softmax → probability distribution over next token
  6. Optimize cross-entropy loss against actual next token
Cross-Entropy Loss: Compares predicted distribution to actual target. Minimizing CE = maximizing log-likelihood.
L = −(1/L) Σᵢ log P_θ(xᵢ | x₁, …, xᵢ₋₁)

Note: Output dimension = vocabulary size (32k–128k), which is why tokenization choices are consequential. Slide 18

Tokenization & Byte-Pair Encoding (BPE)

~14:00 – 18:00

Tokenization converts text into discrete units the model processes. Slides 20–24

Why Not Words or Characters?

StrategyProsCons
Word-levelSemantically meaningfulHuge vocab; fails on rare words/typos
Character-levelTiny vocab; handles anythingVery long sequences → O(L²) cost
Subword (BPE)Balanced vocab & length~3–4 chars/token average

BPE Algorithm

  1. Initialize vocabulary as all individual bytes/characters
  2. Find the most frequent adjacent pair in corpus
  3. Merge that pair into a new token; add to vocab
  4. Repeat until desired vocabulary size reached

Example Slide 22

"unbreakable" → ["un", "break", "able"]
Rare words decompose into known subwords

Implementation Notes

  • Pre-tokenizers split on spaces/punctuation before BPE
  • Retaining small tokens improves robustness to typos
  • Struggles with: long numbers, code syntax, specialized notation
  • Common vocab sizes: 32k (LLaMA), 50k (GPT-2), 100k+ (GPT-4)
🔑 Key Takeaway: BPE gives the best trade-off — manageable vocabulary for efficient softmax, short sequences for fast attention, and robustness to unseen words.

Evaluation: Perplexity & Benchmarks

~18:00 – 22:00

Perplexity Slides 25–28

Perplexity = exponentiated average per-token cross-entropy. Intuitively: "how many tokens is the model choosing between on average?"
PPL = exp( −(1/L) Σ log P(xᵢ | x<ᵢ) ) = 2^(CE Loss)
PerplexityInterpretation
1Perfect prediction
10–20Good model — choosing among ~10-20 plausible tokens
≈ |V|Uniform random (worst case)

Limitation: Depends on tokenizer & test set → cross-model comparison unreliable.

Task-Based Benchmarks Slides 29–32

  • MMLU — 57-domain college-level MCQ
  • HELM — Holistic Evaluation of Language Models
  • HuggingFace Open LLM Leaderboard

Evaluation Challenges

  1. Inconsistent protocols — different orgs report divergent results
  2. Contamination — benchmark data leaks into training sets
Contamination Detection: Compare likelihood of test examples in original order vs. random permutation. Higher in original order → data was seen during training. Slide 31
🔑 Key Takeaway: Perplexity is useful for dev but not cross-model comparison. Task benchmarks provide standardized evaluation but face contamination and inconsistency.

Scaling Laws & Compute Economics

~24:00 – 25:00+

Scaling laws reveal predictable power-law relationships between compute, model size, data, and loss. Slides 38–42

Key Observations

  • Loss vs. compute/data/params follows log-linear trends
  • Enables extrapolation — predict improvement before spending resources
  • First formalized by Kaplan et al. (2020) at OpenAI

Chinchilla Finding (Hoffmann et al., 2022) Slide 40

Chinchilla Optimal: ~20 tokens per parameter is compute-optimal for a fixed FLOP budget.
ScenarioTokens/ParamRationale
Compute-optimal (Chinchilla)~20Minimizes loss for fixed training budget
Inference-optimal (LLaMA)~150+Smaller model trained longer → cheaper deployment

Cost Economics Slide 41

  • FLOPs ≈ 6 × N × D (N=parameters, D=tokens)
  • Frontier runs: $50M–$100M+
  • Each generation: ~10× more compute
  • Significant energy & carbon costs
🔑 Key Takeaway: Scaling laws let teams predict performance before training. Chinchilla showed many models were undertrained. The LLaMA approach (more tokens, smaller model) reflects deployment economics.

Review & Self-Test

Q1: What are the five components that determine LLM performance?

Reveal Answer

Architecture, Training Loss/Algorithm, Training Data, Evaluation, and Systems/Infrastructure. Industry prioritizes data, eval, and systems.

Q2: What is the core pre-training objective?

Reveal Answer

Next-token prediction — minimize cross-entropy loss L = −(1/L) Σ log P(xᵢ | x<ᵢ), equivalent to maximizing log-likelihood.

Q3: Explain pre-training vs. post-training.

Reveal Answer

Pre-training: self-supervised next-token prediction on web data → general language knowledge. Post-training: SFT + RLHF/DPO → aligns model to follow instructions and be helpful/harmless.

Q4: Why BPE over word-level or character-level tokenization?

Reveal Answer

Word: huge vocab, fails on rare words. Character: very long sequences (O(L²) cost). BPE: balanced vocab (~32k–100k), manageable sequence length, handles unseen words via subword decomposition.

Q5: What does perplexity of 15 mean?

Reveal Answer

On average, the model is as uncertain as choosing uniformly among ~15 options per token. Lower = better (1 = perfect).

Q6: What is the Chinchilla finding?

Reveal Answer

~20 tokens/parameter is compute-optimal. Many prior models (GPT-3) were undertrained for their size. LLaMA later showed ~150 tok/param gives smaller, cheaper-to-deploy models.

Q7: How do you detect benchmark contamination?

Reveal Answer

Compare model likelihood of test examples in original order vs. random permutation. Much higher in original order → data leaked into training.

Q8: How many FLOPs to train N parameters on D tokens?

Reveal Answer

~6ND FLOPs. Example: 70B params × 2T tokens = ~8.4×10²³ FLOPs.
